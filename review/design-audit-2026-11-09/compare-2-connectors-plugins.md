## 3. Things the research missed (in this scope)

1. **The lanes file's `test_first` is ignored.** The engine picks test-first by the lane name "bug" (`af:src/core/dispatch/table.ts:277-279`). DESIGN says the engine "acts on a lane's properties, never on its name" (`af:docs/DESIGN.md:84`). `sk:.../lanes.json` sets `test_first` per lane, and nothing reads it.
2. **A card claims a guardrail the engine does not have.** test-first says "the engine refuses a commit that changes a file other than a test". No push guard does that (`af:src/core/finish.ts:75-114`). The engine also drops the "(test files only)" scope from tools (`af:src/core/process/cards.ts:110-118`).
3. **Plugin pins are per machine.** Pins live in `<home>/projects/<project>.plugins.json` (`af:src/core/process/pins.ts:6`). A team layer cannot pin one commit for everyone. Two colleagues can run different rulebook commits. This hurts R13.
4. **DESIGN.md:136 says update runs the eval set; the code does not** (#293, `af:src/plugin-pin-cli.ts:4-5`). Nothing runs the role evals in skills either.
5. **Connector dry mode and kit cases are not built.** `af:docs/DESIGN.md:150-151` names a dry mode and kit cases (approve, stale after edit, refuse a bot). Grepped "dry", "stale", "bot" in `af:src/core/plugin/kit.ts`: none.
6. **Two `plugin update` commands mean different things.** One for connectors, one for Claude plugins (`af:src/app.ts:109-111`). The CLI still says "plugin" for a connector. DESIGN tracks the rename (`af:docs/DESIGN.md:254`, #144).
7. **The tracker slot is built too.** Tickets are local START and spec files (`af:src/core/start.ts:6`; `af:docs/DESIGN.md:180-184`). The README buy-vs-build table lists only the orchestrator, box and egress.
8. **The Copilot coordinator session has no repo-skill guard.** `copilotArgs` passes no `--no-custom-instructions` (`af:src/core/coordinator.ts:207-215`). Whether that session reads a product repo's `.claude/skills`: not verified.
