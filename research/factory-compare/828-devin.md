# #828 — Profile: Devin (devin.ai)

Part of map #826. Read on 2026-11-20. Each claim is *documented* (with a link) or "unknown" with the reason. Devin is
closed source, so no claim here is *inferred from code*. A link to `docs.devin.ai/...md` is the Markdown copy of that
docs page.

## What it is

| Fact | Claim | Source |
|---|---|---|
| What | "an autonomous AI software engineer that can write, run and test code" | *documented* [devin-intro](https://docs.devin.ai/get-started/devin-intro.md) |
| Maker | Cognition (cognition.ai, now cognition.com). Cognition bought Windsurf in July 2025 | *documented* [cognition.ai/blog/windsurf](https://cognition.ai/blog/windsurf) |
| Who for | Engineering teams, from self-serve (Free, Pro, Max, Teams) to Enterprise and Federal (FedRAMP, air-gapped) | *documented* [billing](https://docs.devin.ai/admin/billing.md), [federal](https://docs.devin.ai/federal/introduction.md), [devin.ai](https://devin.ai) |
| Surfaces | Devin Cloud (web app.devin.ai), Devin Desktop, Devin CLI (`devin`), Slack, Teams, Linear, Jira, GitHub PR comments, API, MCP | *documented* [devin-intro](https://docs.devin.ai/get-started/devin-intro.md), [llms.txt](https://docs.devin.ai/llms.txt) |
| Licence | Closed, commercial SaaS. The CognitionAI GitHub org holds helpers only: `devin-cli` holds no source (README, `npm/`, `scripts/`, no licence), `devin-marketplace` (MIT), `devin-outpost-k8s` (MIT, Rust), `devin-connect` (Apache-2.0, Rust), `terraform-provider-devin` (Apache-2.0, Go), `claude-code-on-devin` (no licence) | *documented* `gh api orgs/CognitionAI/repos`, `gh api repos/CognitionAI/devin-cli/git/trees/HEAD` |
| Billing unit | ACU (Agent Compute Unit); Enterprise pays per ACU at the order-form rate. The docs read did not define one ACU | *documented* [billing](https://docs.devin.ai/admin/billing.md) |

## Stack

| Layer | Claim | Source |
|---|---|---|
| Language of the agent or backend | unknown: closed source, and no doc or blog post read names it | — |
| Split | "Brain" (agent loop, a stateless service, always in Cognition's cloud) and "Devbox" (the machine that runs commands) | *documented* [enterprise deployment](https://docs.devin.ai/enterprise/deployment/overview.md) |
| Sandbox | One microVM per session, own kernel, isolated storage, network and compute. The hypervisor is in-house, named "otterlink", and scales "to tens of thousands of concurrent machines" | *documented* [what-we-learned-building-cloud-agents](https://cognition.com/blog/what-we-learned-building-cloud-agents), [swe-1-5](https://cognition.com/blog/swe-1-5) |
| Suspend and resume | Snapshots memory, process tree and filesystem at the hypervisor; idle compute shuts down; it resumes on a CI result or a review comment | *documented* [what-we-learned-building-cloud-agents](https://cognition.com/blog/what-we-learned-building-cloud-agents) |
| Environment | A YAML "blueprint" (sections `initialize`, `maintenance`, `knowledge`, `post-build`) builds one snapshot per org, about every 24 h. "Every session boots a fresh copy" | *documented* [blueprints](https://docs.devin.ai/onboard-devin/environment/blueprints.md) |
| Hosting | AWS ("our cloud environment in AWS"); a deployment diagram also says "Cognition's Tenant is Hosted on Azure". Which one runs which part: unknown, because the docs do not say | *documented* [admin/security](https://docs.devin.ai/admin/security.md), [enterprise deployment](https://docs.devin.ai/enterprise/deployment/overview.md) |
| Self-hosted execution | "Outposts": the brain stays in Devin's cloud; a worker (`devin worker start --outpost=<name>`) on your machine claims sessions from a named queue, outbound HTTPS only. Partners: Modal, Daytona, E2B, Cloudflare, Namespace, NVIDIA | *documented* [outposts overview](https://docs.devin.ai/cloud/outposts/overview.md) |
| Queue | An outpost is "a named queue of sessions". The queue technology: unknown, because it is not documented | *documented* [outposts overview](https://docs.devin.ai/cloud/outposts/overview.md) |
| Storage | Session state lives in VM snapshots; Memory is "a persistent Git repository of Markdown notes"; plugins live in "a managed manifest stored in Devin Cloud". The database engine: unknown, because it is not documented | *documented* [memory](https://docs.devin.ai/product-guides/memory.md), [plugins](https://docs.devin.ai/product-guides/plugins.md) |
| LLM providers | CLI: Anthropic, OpenAI, Google, Cognition (`swe`, `swe-1-6-fast`), plus DeepSeek, Kimi, GLM. Cloud is "a compound AI system" that "does not currently support third-party LLM API keys". Own model SWE-1.5 is trained on GB200 and served on Cerebras at up to 950 tok/s | *documented* [cli/models](https://docs.devin.ai/cli/models.md), [enterprise deployment](https://docs.devin.ai/enterprise/deployment/overview.md), [swe-1-5](https://cognition.com/blog/swe-1-5) |
| Which model Cloud uses per step | unknown: not documented | — |

## First note per topic (seeds the #826 matrix)

| # | Topic | What Devin offers | Source |
|---|---|---|---|
| 1 | User interaction | Chat in the web app (Shell, VSCode IDE, Interactive Browser, Progress tab, read-only Side Chats); `@Devin` in Slack or Teams, where a thread is a session (`sleep`, `mute`, `!aside`, `!ask`, `!fast`, `!ultra`); assign or `@mention` in Linear or Jira; `/devin <prompt>` on a PR; voice mode | *documented* [session-tools](https://docs.devin.ai/work-with-devin/devin-session-tools.md), [slack](https://docs.devin.ai/integrations/slack.md), [linear](https://docs.devin.ai/integrations/linear.md), [jira](https://docs.devin.ai/integrations/jira.md) |
| 2 | CLI | `devin`, installed by curl script, brew cask or PowerShell. It runs locally on any of the models above. `devin --cloud` runs a cloud session; it has SSH into cloud sessions and ACP editor hooks (JetBrains, Zed, Xcode) | *documented* [cli](https://docs.devin.ai/cli/index.md), [handoff](https://docs.devin.ai/cli/handoff.md), [llms.txt](https://docs.devin.ai/llms.txt) |
| 3 | Flow and state machine | Session `status`: `new, claimed, running, exit, error, suspended, resuming`; `status_detail`: `working, waiting_for_user, waiting_for_approval, finished, inactivity, user_request` plus quota and billing reasons. Automations start or message a session from a trigger: schedule (RRULE), webhook, GitHub (incl. CI check run), Linear, Jira, Slack. A "dynamic workflow" is a deterministic Python script (`agent()`, `pipeline()`, `parallel()`) that is recorded and resumable by run ID, budget up to 7 days | *documented* [get session](https://docs.devin.ai/api-reference/v3/sessions/get-organizations-session.md), [automations](https://docs.devin.ai/product-guides/automations.md), [dynamic-workflows](https://docs.devin.ai/work-with-devin/dynamic-workflows.md) |
| 4 | Roles and prompts | No fixed role chain. Cognition's stated stance is a "single-threaded linear agent". Reuse comes from Skills (`SKILL.md`, the Agent Skills standard; read from `.agents/skills/`, `.devin/skills/`, `.claude/skills/` and others), which replace Playbooks (sections Procedure, Specifications, Forbidden Actions; macro `!name`). Knowledge (deprecated) and `AGENTS.md`/`CLAUDE.md` are read. CLI subagents: `subagent_explore` (read-only), `subagent_general`, plus custom `agents/<name>.md`. Bots are long-lived owners from templates (QA Engineer, Migration Engineer, Software Factory) | *documented* [dont-build-multi-agents](https://cognition.com/blog/dont-build-multi-agents), [skills](https://docs.devin.ai/product-guides/skills.md), [creating-playbooks](https://docs.devin.ai/product-guides/creating-playbooks.md), [cli/subagents](https://docs.devin.ai/cli/subagents.md), [bots](https://docs.devin.ai/work-with-devin/bots.md), [software-factory](https://devin.ai/bots/templates/software-factory) |
| 5 | Handoff | CLI `/handoff` sends the branch, the uncommitted diff and the conversation to a cloud session; `/handoff` in a cloud session brings the PR branch back to local. Other agents hand off through the Sessions API. Managed Devins: a parent session starts child sessions (own VM, ACU caps) and is woken when they finish, with no polling; children start without asking unless you turn that off. Memory is carried across sessions in a git-backed note store, merged daily by "Dreaming" | *documented* [cli/handoff](https://docs.devin.ai/cli/handoff.md), [devin-handoff](https://docs.devin.ai/work-with-devin/devin-handoff.md), [advanced-capabilities](https://docs.devin.ai/work-with-devin/advanced-capabilities.md), [memory](https://docs.devin.ai/product-guides/memory.md) |
| 6 | Review | Devin Review: `/devin review` or auto-review (on PR created or ready; once or every push). Its Bug Catcher reports Bugs, Flags and Security (Critical or Warning). Auto-Fix triages each finding (fix, validate or escalate). When Devin opened the PR, that session takes the findings first. Configured by `REVIEW.md` at any directory level; effort Normal or Ultra; Custom reviewers and Autoapprover in beta. Hosts: GitHub (full), GitLab, Azure DevOps, Bitbucket. The review model is unknown: not documented | *documented* [devin-review](https://docs.devin.ai/work-with-devin/devin-review.md) |
